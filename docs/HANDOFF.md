# Handoff

State of the project for whoever picks it up next. Last updated 2026-11-21, after 0.8.0 (Postgres as a fifth language).

**Keep this file current:** after every big event (a release, a merged feature, a CI break and its fix, a finished review), update this handoff and commit it as its own `docs(handoff)` commit, without waiting to be asked.

## Where things stand

- **0.8.0** (2026-11-21, not yet pushed or tagged): Postgres is a fifth language. `dist/postgres/scalars.sql` (built by `dev/codegen/postgres.mjs`, embedding the hand-written `dev/codegen/engine.sql`) creates schema `scalars`: per type but `enum`, `scalars.<type>_reason(v)` (NULL when valid, else a `$meta.reasons` name), `scalars.is_<type>(v)` and a `scalars.<type>` domain. Plain SQL/PL/pgSQL, Postgres 16+ (it uses `pg_input_is_valid`), no extensions. Inputs are canonical: normalize stays in the app (Postgres `lower()`/`upper()` depend on the server locale). Text columns get the whole rule (length, pattern, `scalars.check_<name>`, the list as a jsonb object literal tested with `?`: measured 0.07 ms per insert on `language`, against 0.4 ms for `= ANY`). Native columns keep Postgres's parser (the owner's pick: accept its spellings, use its types); the domain adds only what it misses (`domain_check` in `src/targets/postgres.yaml`: IP family, no NaN/infinity, the uuid_v7 version, sha256 length, uint64 range; narrower integer ranges are derived). `scalars.char` is varchar, since char(1) blank-pads. Number functions take JSON number text, parsed as float8; text float8 can't parse is `out_of_range`. A re-run replaces every function and drops and re-adds each domain's `<type>_check` NOT VALID (rows already stored are not rechecked). Dist `postgres.check` is gone; `postgres.domain` and `postgres.domain_check` replace it.
- **0.7.0** (2026-11-21): 14 types removed (75 remain), one type per concept: no `sf_*`, `http_date`, `media_range`, `relative_json_pointer`, `iri*`, `idn_*` or `double_int`. `email` covers international addresses (JSON Schema `format: idn-email`, no HTML `type="email"`); `hostname` and `uri` take international names in ASCII form. 0.6.2 before it made `language` a closed BCP 47 list. Tagged `v0.6.0` to `v0.7.0` on 2026-11-21 after CI passed (`v0.7.0` is on the handoff commit, after the email fix). There is **no compatibility promise before 1.0**: a release may rename, move or remove anything when that gives the cleaner design, and says so in the changelog.
- **Reasons (since 0.6.0):** every failed `validate` carries one reason from `$meta.reasons` (`src/scalar.yaml` `$defs.reasons`): `wrong_kind`, `malformed`, `too_long`, `too_short`, `pattern`, `out_of_range`, `check`, `not_in_list`, in the order the single pass checks them; a value breaking several gets the first. `dev/lib/reference.mjs` defines the order and `dev/langs/cases.json` pins it (every `ok: false` case has a `reason`, with cases where two gates compete). Engines never spell a reason: the names are emitted (TS `Reason` + `FAIL`, Python `Reason` + `_FAIL`, Go `Reason*` constants, Rust `enum Reason`), and a codegen test greps the engines. Models report the reason as the problem `code` (no more `invalid`), with `params.type` on every type-field problem.
- **Closed lists (since 0.6.0):** `country`, `country_alpha3`, `currency` and (since 0.6.2) `language` have a core `enum` (dist `schema.enum`), checked last, after `check`. Sources and dates are in each type's `details` (Debian `iso-codes` for ISO 3166-1, SIX `list-one.xml` for ISO 4217, the IANA Language Subtag Registry for `language`: its `Type: language` records minus `Deprecated` and the private-use `qaa..qtz`, 8,043 codes, about 50 KB per dist file). The registry gives one code per language, so `fra` and `iw` fail. Engines: TS `Set`, Python `frozenset`, Go sorted slice + `slices.BinarySearch` (no map, so no init code), Rust sorted `&[&str]` + `binary_search`, Postgres a jsonb object literal with `?` (a `text[]` binary search would be slower: indexing a variable-width array walks it).
- **Goal:** one JSON definition per data type that works the same in Go, Python, Rust, TypeScript and Postgres (the five languages), plus HTML forms and JSON Schema/OpenAPI. Languages read the core of each type; the `html` and `postgres` blocks only say how those two spell it.
- **Generated code (since 0.4.0):** `dist/python/scalars.py`, `dist/ts/scalars.ts`, `dist/go/` (`scalars.go` and `go.mod`) and `dist/rust/scalars.rs`. One file per language, built from `dist/scalars.json` by `dev/codegen/`. Each has `validate` / `is_valid` per type (and `normalize`: every type in Python and TypeScript, text types in Go and Rust), `get` by name or alias, and `all`. Python and TypeScript need no dependencies, Go needs `golang.org/x/text`, Rust needs `regex` and `serde_json` (each header names the tested versions, read from the runners' `go.mod` and `Cargo.lock` by `lockedVersion` in `dev/codegen/common.mjs`). Rust `Meta` has no examples, and Go leaves out the 4 object-valued ones (in `any`, `array`, `object`) so the package needs no init code.
- **Linear guarantee:** `validate` is O(n) worst case in all four languages. The build rejects any pattern that isn't provably linear, and every check (below) is a single pass with no big integers.
- **Checks (since 0.4.0):** a type can name a rule beyond its pattern with `check`. Seven exist: check digits for `gtin`, `gln`, `iban`, `lei`, `isbn` and `orcid`, and the 64-bit range for `int64` and `uint64` (which used to accept any run of digits, so `validate` passed values Postgres refused). The five languages and `dev/lib/reference.mjs` run them. JSON Schema and HTML check the pattern alone.
- **README is quick-start first:** one `curl` command and a short example per language, then a method table across the four, the core type table, the JSON files (forms, OpenAPI, Postgres), edge cases, and editing types last. Each quick start was run from scratch in a fresh project on 2026-11-13. The download links point at the release tag (`v0.7.0`); move them to the new tag with each release (a test in `build.test.mjs` fails until you do). Keep the method table and examples in step with `dev/codegen/` when the API changes.
- **CI:** `.github/workflows/test.yml` has three jobs on pushes to `main` and on pull requests. `test` runs `npm test`, `npm run check:ts` (`tsc --strict` on `dist/ts/scalars.ts`, TypeScript pinned in `dev/package.json`), `npm run check:langs`, a quick `npm run fuzz:models -- 1 200`, and `go test -race`. `minimums` runs `npm run check:langs` on Python 3.10 and Rust 1.80, the oldest versions the headers promise. `go-minimum` builds and vets a copy of `dist/go` on Go 1.21, the minimum its `go.mod` states (the engines use nothing newer: `slices`, `min`, `max`; `golang.org/x/text` v0.21.0 needs 1.18). Green since its first run on 2026-11-20, except one break: `40b4db5` bounded `unix_time` but gave it only one `invalid` example, failing the conformance test; `57b83c9` added a second (2^53) and CI is green again. Run `npm test` before pushing, not after, and stop on a failure: the 0.5.0 release commit went out with a stray `dist/python/__pycache__` (from importing the dist file in place for a hand check), fixed in the next commit before tagging. CI is the only place `go test -race` runs, since the dev machine has no C compiler.
- **Models (released in 0.5.0):** users declare domains → models → fields as parsed JSON; every language has `models(data)`, `get("domain:model")`, `validate` and `is_valid`, reporting every bad field as `{pointer, code, params, message}`. The behaviour is defined by `dev/lib/models.mjs` and the shared `models` cases in `dev/langs/cases.json`; each language's hand-written engine is `dev/codegen/models.{py,ts,go,rs}`. Error templates live once in `src/scalar.yaml` `$defs.errors` (→ `$meta.errors`). Rust now also needs `serde_json`. The spec and plan are `docs/superpowers/specs/2026-11-20-models-design.md` and `docs/superpowers/plans/2026-11-20-models.md`.
- **Models constants live once:** `MAX_DEPTH`, the `NAME`/`REF` patterns and the digit settings are exported by `dev/lib/models.mjs` and emitted into the generated files next to `PARAM_RULES` (Go and Rust get `MAX_DEPTH` only; they parse names by hand and wire `precision`/`scale` into the logic, pinned by the shared cases). A codegen test fails if a hand-written engine defines them again.
- **Only `models()` builds a `Model` or `Models`:** TS and Python constructors take a module-private key and throw `TypeError` otherwise. Go's `Model.Name()` and `ModelSet.All()` are methods (`All` returns a copy), as in Rust.
- **Tests, all passing:** `cd dev && npm test` (342 tests: JSON Schema, the browser's regex engine, real Postgres via PGlite, the models reference) and `npm run check:langs` (TypeScript, Python, Go, Rust, including the shared models cases, and Postgres: `dev/langs/check.pg.mjs` loads the SQL into PGlite, normalizes text with the reference first, and runs every example plus the validate, hostile and match cases; it skips malformed text, non-strings into a text type, and `enum`. The models fuzzer leaves Postgres out). `npm run fuzz:models -- [seed] [count]` (`dev/langs/fuzz.mjs`) generates random models files and payloads, takes the answers from `dev/lib/models.mjs`, and runs all four runners on them (on top of the shared cases); it prints the seed so a failure can be rerun. Seeds 1-5 at 600 files each (39,928 payloads) found no disagreement on 2026-11-21. Run more seeds by hand after an engine change; reduce any disagreement to a named shared case in `cases.json`.
- **Adding to models:** a new behaviour goes into the reference first, with a shared case; then all four engines. Mutation tests during the build kept finding behaviours no shared case pinned, so when you change an engine, plant a bug and check a shared case catches it.

## How a type reads in dist (since 0.3.0)

- `primitive`: one of 16. It's all a language needs to choose a native type.
- `schema`: plain JSON Schema keywords (`type`, `format`, `pattern`, `minLength`, `maxLength`, `minimum`, `maximum`, `contentEncoding`).
- `params`: settings a field can take (`length`, `precision`, `scale`, `fractional_seconds`, `values`), defined once in `$meta.params`. `nullable` applies to every type and isn't listed.
- `normalize`: cleanup steps, defined in `$meta.normalize_steps`. `$meta.lookup` gives the rule for finding a type from a word.
- `check` (on 8 types): a rule run on the normalized value after the pattern matched, defined in `$meta.checks`. `examples.check_invalid` holds values that pass the pattern but fail the check.
- `html`, `postgres`: generated pattern, CHECK and attrs. `postgres.attr` names entries in `$meta.postgres_attrs`; only `enum` and `duration` have one.

## Rules that are easy to break

- **Patterns must be provably linear** (`dev/lib/linear.mjs`). The build fails on nested repeats that yield the same step twice, or on ambiguity that grows with the input. If it rejects a pattern, rewrite it to name one split point, as `email` does.
- **Patterns use the portable subset** (`dev/lib/portable.mjs`, based on RFC 9485): no `\d \s \w`, no `.`, no lookaround or backreferences, no leading `]` in a class, and no `\xHH` followed by a hex digit. The build fails otherwise. Write `[0-9]`, not `\d`.
- **Python:** use `re.fullmatch`, since `$` alone also matches before a trailing newline. Python's `str.strip()` and JS's `trim()` use different whitespace sets from the trim step, so implementations write the set out.
- **Go:** case steps need `golang.org/x/text/cases`. `strings.ToLower` turns `İ` into `i` and leaves `ß` alone.
- **Text must be well-formed Unicode:** JS and Python strings can hold lone surrogates and Go strings can hold invalid UTF-8; every engine (and `reference.mjs`) rejects them right after trim, before `remove_*` steps (which could join two halves in JS and Go but not Python) and after an exact over-length gate (counting stops at the limit; a lone surrogate counts as one code point, in Go too: `codePoints` in `engine.go` counts the 3-byte form `ED A0..BF 80..BF` as one), so over-long malformed text is `too_long` everywhere. Rust's `&str` can't hold them. Cases marked `"malformed": "surrogate"` are skipped by the Go and Rust runners, since their JSON decoders can't carry a lone surrogate.
- **Lengths count code points** everywhere except the HTML `maxlength` attribute, which counts UTF-16 units.
- **Only text types take `precision` or `scale`:** the build refuses them on a number, since float text differs by language.
- **A text type taking `precision` needs a digits pattern** (`-?[0-9]+(\.[0-9]+)?` or a narrower form, listed in `DIGIT_PATTERNS` in `dev/lib/resolve.mjs`); the build fails otherwise, since the digit counting assumes that shape.
- **Enum values are at most 63 bytes as UTF-8** (`maxItemBytes` in `$meta.params.values`, the Postgres label limit, checked against PGlite). Postgres accepts an empty label, so `""` is allowed.
- **`params` is not inherited**: list it on every type that takes it. Every other core key is inherited from `base` (`null` deletes).
- **Every type with a rule needs at least 2 `invalid` examples,** and a rule means a `pattern`, a `minimum` or a `maximum`. Adding bounds to a type that had none (as with `unix_time`) makes it need them.
- **Every type with a `check` needs at least 2 `check_invalid` examples, and no other type may have any.** They must pass JSON Schema and the HTML pattern. Range values that Postgres rejects also go in `db_invalid`, since `check_invalid` values are never inserted into Postgres.
- **Adding a check touches four places:** `schema/scalar.schema.json` `$defs.check` (name and meaning), `CHECKS` in `dev/lib/reference.mjs`, and each `engine.*` (including `engine.sql`: `scalars.check_<name>`, bytes via `convert_to` + `get_byte`, never `substr` in a loop; the emitter fails the build if it's missing). In `engine.go` name the constant `check` + the PascalCase check name (`iso7064_mod11_2` → `checkIso7064Mod112`); in `engine.rs` name the `Check` variant the PascalCase name (`Iso7064Mod112`). The emitters derive those names and fail the build if the engine lacks them or two names collide. A new normalize step works the same way (`step` + PascalCase in Go, a PascalCase `Step` variant in Rust). Port a check over ASCII bytes or code units, reduce mod as you go (no big integers, no growing totals), and run it only after the pattern matched.
- **A type with an `enum` needs at least 2 `list_invalid` examples, and no other type may have any.** They pass the pattern and normalize but are not on the list. The build checks each `enum` is text-only, sorted with no repeats, matches the pattern and is unchanged by normalize; `enum` is inherited, so a child with another pattern (as `country_alpha3` under `country`) must set its own.
- **A list update is a patch release (0.6.x),** shipped soon after ISO announces the change: an older release rejects a code ISO added after it. ISO 4217 changes about once a year, ISO 3166-1 rarely. Re-download, regenerate the arrays, update the source line in `details`.
- **`invalid` examples are raw-pattern rejects:** a few become valid after `normalize` (e.g. `country` "us"), and the runners accept that only when normalize changes the value.
- **Postgres domains:** a native column's extra rule is a `domain_check` over `VALUE` in `src/targets/postgres.yaml` (inherited from `base`; a child repeating it fails the dry test). Text columns get `scalars.is_<type>(VALUE)` generated. A new native type needs a look at what its Postgres type accepts that the core rule refuses (NaN, infinity, other families).
- **Generated files:** never edit `dist/python`, `dist/ts`, `dist/go`, `dist/rust` or `dist/postgres` by hand. Change `dev/codegen/` and run `npm run build`. The hand-written parts are `dev/codegen/engine.{py,ts,go,rs,sql}`.
- **Source is YAML 1.2:** patterns go in single quotes (`'^[0-9]+$'`), where no backslash is ever doubled. Quote any value a YAML 1.1 tool would mistype (`'NO'`, `'on'`, `'0'`, `'true'`): `source.test.mjs` fails if a file reads differently under 1.1 and 1.2. Long code lists are flow sequences packed to 120 columns; keep them sorted. The Bash tool on this Windows machine still collapses `\\` to `\` in heredocs, even quoted ones, so a script that writes a backslash goes through the file editor.
- **Don't import `dist/python/scalars.py` in place:** it leaves a `__pycache__` that fails "dist holds only built files". Copy the file elsewhere, or run with `-B`.

## Layout

- `src/`: what you edit, in YAML 1.2. `scalar.yaml` holds the core, `targets/html.yaml` and `targets/postgres.yaml` hold the two targets. `dev/lib/source.mjs` reads them (the `yaml` dev dependency, pinned exact).
- `dist/`: the generated release. `npm run build` rewrites it, and a test fails if the committed copy is stale.
- `schema/`: JSON Schemas for the source and dist files.
- `dev/codegen/`: the generator. `model.mjs` is the shared model, `generate.mjs` drives it, `python.mjs` `ts.mjs` `go.mjs` `rust.mjs` `postgres.mjs` write each language, and `engine.*` is the hand-written runtime each one embeds.
- `dev/`: build, tests, and `dev/langs/` (one runner per language, plus the shared `cases.json`).
- `.github/workflows/test.yml`: CI.
- `coding/`: the owner's own gitignored scratch folder. Leave it alone.

## Models follow-ups: settled

All the findings from the models branch's reviews were worked through on 2026-11-21, before 0.5.0. Fixed: constructors (only `models()` builds a model), Go `Name`/`All` as methods, Rust `Value::from(&Problem)`, versions read from the lock files, `header()` failing on an unknown extension, the wider `metaFields` and models-schema tests, CI on Python 3.10 and Rust 1.80, the models constants emitted once, the 63-byte enum limit, the digits-pattern build check, and the README wording. These were decided, not changed:

- **Python returns a float for number fields** (`3` → `3.0`). Kept: Go, Rust and TS hold a float64 too, only the printed text differs, the README says so, and 0.4.0 scalars already did it.
- **Alias collisions** were already guarded: `test/human.test.mjs` fails if two types share an alias or an alias is a type name.
- **Go's `mod97` helper** keeps its name: it serves both `iso7064_mod97_10` and `iban`, named the same in all four engines.
- **Loose engine-name regexes** in the emitters stay; each compiler rejects a name the engine lacks.
- **Go payloads** must be what `encoding/json` produces (no `int`, `[]string`, `json.Number`). That's the spec, and the README says so; revisit if Go users ask.
- **Shared shape values:** `object` and `any` values come back as the input's own object in Python, TS and Go, a copy in Rust. Documented in the README.

## Postgres follow-ups (deferred minors from the 0.8.0 review)

- `SET standard_conforming_strings = off` in a session makes `\.` in a pattern mean any character (and loading fails): emit patterns as `E'...'` with doubled backslashes.
- A session `search_path` placing a schema before `pg_catalog` can shadow `char_length` or `~` inside the functions: qualify `pg_catalog.` / `OPERATOR(pg_catalog.~)`.
- `check_int64_range` / `check_uint64_range` return true for non-digits (as the reference does; the reason functions run the pattern first). `engine.sql`'s header says false.
- `1e-400` is `out_of_range` (the reference accepts it as 0), and `1e400` into an integer type is `out_of_range` (the reference: `wrong_kind`). No shared case pins either.
- README: say `<type>_reason(NULL)` is NULL (so `IS NULL` counts NULL rows as valid); suggest `psql -v ON_ERROR_STOP=1 -1 -f scalars.sql`; the "Fast on any input" bullet says four languages.
- Later, if wanted: models emitting `CREATE TABLE`.

## Possible next steps (none promised)

- Add or fix types without changing the shape. Each new type needs `valid` examples, at least 2 `invalid` ones if it has a rule, and a `level`.
- `format`-only types (dates, `uri`, …) are checked by pattern where they have one. Their `format` keyword isn't validated by the runners.
- Follow-ups from the `docs/info.md` review (approved in principle, not designed):
  - **A `language` list:** done in 0.6.2 (BCP 47, IANA registry). Skip `timezone` and `subdivision`, whose lists change too often or are too big.
  - **New identifier types** (`sscc`, `un_locode`, `gpc_brick`, `spdx_license`): dropped on 2026-11-21. The owner wants the data kept free of types that won't be used; add a type only when it checks something real and appears as field data.
- Deferred on purpose: units and quantities (UCUM, which needs two fields, so a schema), translated labels, hints and errors, and JSON-LD mappings.
