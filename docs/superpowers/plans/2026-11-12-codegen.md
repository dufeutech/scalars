# Code Generation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Generate one copy-in file per language (`dist/python/scalars.py`, `dist/ts/scalars.ts`, `dist/go/scalars.go`, `dist/rust/scalars.rs`) from `dist/scalars.json`, with `scalars.<type>.validate()` in O(n) worst case in every language.

**Architecture:** A build-time proof (`dev/lib/linear.mjs`) rejects any pattern a backtracking engine could run in more than linear time, and also yields each pattern's shortest and longest match. A shared model (`dev/codegen/model.mjs`) turns dist into one flat record per type. Each language has a hand-written engine (`dev/codegen/engine.*`) and a small emitter (`dev/codegen/<lang>.mjs`) that appends a generated table to it. The four `dev/langs/` runners stop re-implementing the rules and import the generated files instead.

**Tech Stack:** Node ≥ 22 (`node:test`) for the build; Python ≥ 3.10; TypeScript run directly by Node (erasable syntax); Go ≥ 1.21 with `golang.org/x/text`; Rust ≥ 1.80 (edition 2021) with `regex`.

**Spec:** [`docs/superpowers/specs/2026-11-12-codegen-design.md`](../specs/2026-11-12-codegen-design.md). Executors read both. The spec's Complexity guarantees table is the acceptance bar.

## Global Constraints

- `validate` is O(n) worst case for every type, in all four languages, on hostile input. Nothing runs at load beyond building the records.
- No regex anywhere in trim, the other normalize steps, or lookup key cleanup. Regexes only for type patterns, compiled once per type, on first use.
- Generated files are fully generated: `npm run build` writes them and the stale-dist test fails if a committed copy differs.
- No rule is copied by hand: patterns, messages, steps, lengths and bounds come from `dist/scalars.json` (or are derived from it by `linear.mjs`).
- The shape of `dist/scalars.json` does not change. Derived lengths are not added to it.
- Python and TypeScript files have no dependencies. Go: `golang.org/x/text`, Rust: `regex`; each file's header names them with the tested version.
- Generated TypeScript uses erasable syntax only: no `enum`, no `namespace`, no parameter properties.
- Names: Python and TypeScript use the dist name as is; Go uses plain PascalCase (`uuid_v7` → `UuidV7`); Rust uses SCREAMING_SNAKE (`UUID_V7`). Engine names are reserved, and the build fails on any collision.
- Errors carry the type's `error` text exactly, and the type.
- Windows: the Bash tool collapses `\\` to `\`. Edit any file that holds a pattern with the file editor, never a shell heredoc. Files are UTF-8 with LF line endings.
- Work on a branch, not `main`. Commit after each task. Commit messages end with the attribution lines the session gives.

## Review Focus

1. **A type name that shadows a builtin** (`any`, `object`, `all` in Python; `enum` in TS): the engine must still work. Task 3 tests `scalars.any.validate(...)` and `scalars.object.validate(...)`, and Task 4 tests `scalars.enum.validate(...)`.
2. **Text that becomes longer or shorter when case-mapped** (`ß` → `SS`, `İ` → `i̇`): the length gate must not reject what the full pipeline would accept. The gate runs on the trimmed text against the max only, because case mapping never shortens. A `validate` case in Task 2 pins `country` on `"ß"` (rejected by the pattern, not by a crash).
3. **Non-string input to a text type in Python/TS** (`None`, `123`, a list): `is_valid` returns false and `validate` raises `ScalarError`, never `TypeError`. These are cases in Task 2.
4. **Concurrency in Go**: two goroutines validating `Slug` (lowercase step, non-ASCII input) at once. Task 5 adds a test run with `-race`.
5. **A word that is an alias and also a different type's name after cleanup**: lookup tries the exact word first, then the cleaned key. Both paths must give the `$meta.lookup` answer. Task 2's lookup cases cover `"Phone Number"`, `"MAIL"` and a miss.

- [ ] **Step 3: Implement `dev/lib/linear.mjs`**

The parser covers exactly the subset `portable.mjs` allows: literals, `\xHH`, literal escapes, classes (ranges, `^` negation) as sorted code-point interval lists over `[0, 0x10FFFF]`, `(...)`, `(?:...)`, `|`, `* + ? {n} {n,} {n,m}`, and `^`/`$` at the ends only. Node kinds: `class`, `concat`, `alt`, `repeat {min, max}`.

`matchLengths` folds the AST: a class counts 1, concat sums, alt takes min/max, repeat multiplies.

`linearProblems` uses this algorithm (there's no library for it):

1. Widen every repeat whose `max > 4` (and `{n,}` with `n > 4`) to `{min(n,1)…∞}`, i.e. `*` or `+`. Expand the rest by copying. Widening only adds parses, so a pass stays sound.
2. Build the Glushkov (position) automaton: one state per class occurrence plus a start state. **Every state counts as accepting**, because backtracking explores all prefixes of a failing input. Two transitions "share a letter" when their target classes intersect.
3. **EDA**: build the pair automaton over (p, q) with edges where both moves share a letter. EDA exists iff some strongly connected component contains a diagonal state (p, p) and a non-diagonal state. Report `exponential ambiguity at positions i/j`.
4. **IDA**: build the triple automaton over (p, q, r) with edges where all three moves share one letter. IDA exists iff for some p ≠ q the state (p, p, q) reaches (p, q, q). Report `polynomial ambiguity between positions i and j`.

Keep the code readable; size isn't a concern, since the largest dist pattern stays under about 80 positions.

**Interfaces:**
- Produces: `toModel(scalars) → Model[]`, in dist order (alphabetical). One record per type:
  `{ name, label, hint, error, details, level, primitive, aliases: string[], examples: {valid, invalid},
    kind: "text"|"integer"|"number"|"boolean"|"object"|"array"|"any", steps: string[], pattern: string|null,
    minLen: number, maxLen: number|null, minimum: number|null, maximum: number|null }`
  - `kind` comes from `schema.type`, and is `"any"` when absent.
  - `minLen` = max(`schema.minLength` ?? 0, the pattern's min). `maxLen` = min(`schema.maxLength`, the pattern's max), or `null` if both are unbounded. Only text types have lengths.
- Produces: `identifiers(models, lang, reserved: string[]) → Map<name, identifier>`, which throws `Identifier "<id>" is used by "<a>" and "<b>"` on any collision, including with a reserved name.
- Produces: `generate(scalars) → Record<string, string>`, mapping a path relative to `dist/` to its file text. Starts empty. Tasks 3–6 each register one emitter: `emit(models, version) → Record<path, text>`.
- Produces: `reference.validate(t, v) → { ok: boolean, value? }`, following spec semantics (below).
- Produces: the `cases.json` formats (below), used by every runner.

**`validate` semantics** (all languages):

- **Text.** It must be a string, else no. Then trim if the type has the trim step. Then gate the length: if the code-point count is above `maxLen`, reject before case mapping. Then the remaining steps in order. Then the full length check (`minLen`…`maxLen`). Then the pattern. The value returned is the normalized text.
- **Integer.** A number (not a boolean) that is finite and has no fractional part (`3.0` counts, per JSON Schema), within `minimum`/`maximum`. The value returned is the integer.
- **Number.** A finite number (not a boolean), within bounds.
- **Boolean.** A boolean.
- **Object / array / any.** Only the JSON kind is checked.

How runners treat these cases:

- Runners compare a failure's message to the type's `error`.

- **Go `ShapeScalar[T]`**, and Rust object/array/any as plain `Meta`, as the spec says.
- **Lookup returns metadata, plus a typed lookup.** In Go and Rust, `Get`/`get` return metadata only, because their types differ per kind. The typed `Lookup`/`lookup` functions exist for tools such as the runners.
- **No examples in Rust**, because there's no JSON type to hold them without a dependency.
- **The hostile cases are the benchmark.** Each runner prints its slowest hostile case in ms, in place of separate bench scripts per language.
- **`dist/go/go.mod` is generated**, so the Go runner can use a `replace` and users get a ready module directory.
