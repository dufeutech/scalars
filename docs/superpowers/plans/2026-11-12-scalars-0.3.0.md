# Scalars 0.3.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make `dist/scalars.json` mean the same thing in Go, Python, Rust and TS, simplify its shape once, prove it in all four languages, then freeze the shape.

**Architecture:** Source stays in `src/`, the build in `dev/`, the release in `dist/`. Every rule a language needs (pattern, bounds, params, normalize, lookup) lives in the core of each type, never inside a target. Targets (`html`, `postgres`) only say how to spell the core in their world.

**Tech Stack:** Node ≥22 (`node:test`, ajv 8.20.0, PGlite 0.2.17) for the build; Go 1.26, Python 3, Rust (cargo 1.97), TS/Node for the runners.

**Spec:** this conversation's review (2026-11-12), summarized here:
1. Patterns use a portable subset (based on RFC 9485 I-Regexp), enforced by the build.
2. Type parameters move from `postgres.$defs.attr` into the core.
3. `primitive` is a closed enum; the JSON Schema keys sit under one `schema` key; `category` and `$meta.templates` are dropped; `check_extra` becomes `check`.
4. One small runner per language checks every example against `dist/scalars.json`.
5. Release 0.3.0 and freeze the shape: later releases only add or fix types.

## Global Constraints

- `dist/` stays plain JSON that needs no code to read. Lookups by name in one flat `$meta` map are allowed. Inheritance and references are not.
- No per-language targets (`targets/go.json` and the like). Languages read the core.
- Every pattern is anchored `^...$` and uses only the portable subset (Task 1).
- `npm test` in `dev/` must pass after every task, and `dist/` is rebuilt and committed in the same commit as the source change.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Python `$`** matches before a trailing `\n`: `"+14155552671\n"` must be rejected. The Python runner uses `re.fullmatch` (Task 4 test).
2. **Non-ASCII digits** (`"+1٣٣٣"`) must be rejected by every engine (Task 1 test, then every runner in Task 4).
3. **A hostname over 253 characters** must be rejected once the lookahead is gone (Task 1 invalid example).
4. **Enum values** must reach HTML and the languages without reading `postgres.*` (Task 2 test).
5. **Old field names** (`category`, `check_extra`, `postgres.attr.labels`) must not appear anywhere in `dist/` (Task 3 test).

### Task 1: Portable patterns

**Files:**
- Create: `dev/lib/portable.mjs`, `dev/test/portable.test.mjs`
- Modify: `src/scalar.json` (44 patterns use `\d`, `media_range` uses `\s`, `hostname` and `duration` use lookaround), `dev/lib/derive.mjs` (call the check, add `maxLength`), `dev/lib/resolve.mjs` (`INHERITED` gains `maxLength`), `schema/scalar.schema.json`, `schema/dist.schema.json`, `dist/*`

**Interfaces:**
- Produces: `patternProblems(pattern: string) -> string[]` in `dev/lib/portable.mjs`. An empty array means portable.
- Produces: the core key `maxLength` (integer), inherited like `pattern`, emitted into JSON Schema and openapi, as HTML `maxlength` on text inputs, and as `char_length({column}) <= N` in the generated Postgres CHECK.

**The portable subset (allowlist):** anchored `^...$`; literals; `[...]` and `[^...]` with ranges; quantifiers `* + ? {n} {n,} {n,m}`; groups `(...)` and `(?:...)`; `|`; escapes are only `\` + one of ``\^$.*+?()[]{}|/-`` or `\xHH`. Anything else is a problem: `\d \D \w \W \s \S \b \B \p{..}`, backreferences, lookaround, named groups, any other `(?`, **`.`** (JS excludes `\r`, U+2028 and U+2029; the others exclude only `\n`), **a leading `]` in a class** (JS reads `[]` as empty), and **`\xHH` followed by a hex digit** (Postgres keeps reading hex).

**Found during execution (scope added to Task 1):** `email` used `[^@\s]` → `[^@\x09-\x0D\x20]`. `char` used `[\s\S]` → no pattern, `minLength: 1` + `maxLength: 1` instead (code points everywhere). `media_type`/`media_range` used `.*` → `[^\x00-\x1F\x7F]*`, and `media_range` `\s*` → `[\x09\x20]*`. So `minLength` is a core key too: HTML `minlength`, and `char_length({column}) >= N` in the CHECK. `char`'s hand-written HTML `maxlength` became generated.

**Verified:** a 300k-sample fuzz per changed pattern shows the same accept/reject as before on ASCII input, apart from the intended tightening in the media types (control characters, and CR/LF before `;`). Go `regexp` and Python `re.fullmatch` against the new `dist`: 50/50 patterns compile, 0 example failures, `+1٣٣٣` rejected (before: Go failed to compile 2 patterns, Python accepted `+1٣٣٣`). Rust is still unverified until Task 4.

### Task 2: Type parameters move into the core

**Files:** `src/scalar.json` (new top-level `$defs.params`, per-type `params` list), `src/targets/postgres.json` (`$defs.attr` keeps only Postgres-only attrs: `collation`, `fields`, `name`), `src/targets/html.json` (enum `options` no longer has `source: "postgres.attr.labels"`), `dev/build.mjs`, `dev/lib/resolve.mjs`, the schemas, the tests.

**Interfaces:**
- Produces: `dist.$meta.params`, a flat map from param name to definition (`type`, bounds, `default`, `description`). The names are `length`, `precision`, `scale`, `fractional_seconds`, `values` (renamed from `labels`) and `nullable`.
- Produces: `types.<name>.params: string[]`, **not inherited** (each type lists its own). Inheriting needed `null` on 46 types; listing it needs 3 extra lists.
- Produces: `dist.$meta.postgres_attrs` (`collation`, `fields`, `name`, each with `sql`) and `types.<name>.postgres.attr: string[]`, used only by `enum` (`name`) and `duration` (`fields`).
- **`nullable` and `collation` apply to every type / every text column**, so they're defined once and never listed per type. That removes the 44 inline `collation` copies and all the `"attr": null` lines in the source.
- Params carry no SQL examples. Each description says how HTML and Postgres spell it (for example "HTML: maxlength. Postgres: varchar(n).").

- [x] Test (`dev/test/params.test.mjs`): `$meta.params` has exactly the 6 names; every listed name exists; the exact type → params map; only `enum`/`duration` have `postgres.attr`; `enum.html.options` is gone and nothing in dist contains `postgres.attr`.
- [x] Implement, rebuild, `npm test` (148/148). `dist/scalars.json` 107.7 KB → 98.0 KB.
- [x] Commit `refactor: move type parameters from postgres into the core`.

### Task 3: Shape cleanup

**Files:** `dev/build.mjs`, `dev/lib/resolve.mjs`, `dev/lib/derive.mjs`, `src/*.json`, `schema/*.json`, tests, README.

**Interfaces:**
- Produces: `types.<name>.schema`, the **validation keywords only** (`type`, `format`, `pattern`, `minLength`, `maxLength`, `minimum`, `maximum`, `contentEncoding`). Grouping happens in `build()` (`groupSchema` in `derive.mjs`), so `resolve()` stays flat. `openapi.json` `components.schemas[n]` = `{...schema, title: label, description: hint, examples: examples.valid}` (byte-identical to 0.2.0's). `toJsonSchema` stays as a test helper on flat types. *(Changed from the first draft: keeping `title`/`description`/`examples` out of `schema` avoids repeating `label`/`hint`/`examples` in every type.)*
- Produces: in `dist.schema.json`, `primitive` is an `enum` of the 16 names in `PRIMITIVES`, and `PRIMITIVES` is read from that schema rather than kept in JS.
- Removes: `category` (source, schema, dist), `$meta.templates` (the `{column}` sentence moves into the `postgres.check` description in `dist.schema.json`).
- Renames: postgres `check_extra` → `check` (a hand-written check overrides the generated one).

- [x] Test (`dev/test/shape.test.mjs`): `dist` contains no `category`, `check_extra`, `templates`, `labels` or `"postgres.attr`; `openapi.components.schemas[n]` equals schema + label, hint and valid examples for every type; hand-written `uint64` check wins; every `primitive` is in the schema enum.
- [x] Implement, rebuild, `npm test` (153/153), README example updated, commit `refactor!: group validation under schema, close primitive, drop category`.

### Task 4: One runner per language

**Files:** `dev/langs/` (`check.ts`, `check.py`, `go/`, `rust/`, `run.mjs`, `cases.json`). *(Changed from the first draft: the user's gitignored `coding/` folder is left untouched. Runners are dev tooling, so they sit beside the build.)* Dependencies: Go `golang.org/x/text`, Rust `regex` + `serde_json`. Python and TS use only the standard library.

**Interfaces:**
- Consumes: `dist/scalars.json` and `dev/langs/cases.json` (both paths as arguments).
- Each runner: for every type whose `schema.type` is `string`, every string in `examples.valid` must pass `pattern` + `minLength`/`maxLength` (code points) and every string in `examples.invalid` must fail. Then it runs the shared `cases.json` (`normalize`, `lookup`, `match`). It prints `<lang>: ok, 88 types` or lists failures and exits 1.
- Engines: Go `regexp`, Python `re.fullmatch`, Rust `regex`, TS `new RegExp(p, "u")`.

**Found during execution:**
- The lookup rule's text ("turn spaces and '-' into '_'") disagreed with the reference code (collapsed runs, JS `\s`, JS `trim()` which strips U+FEFF). Both now say: the trim step, the lowercase step, each run of spaces and `-` becomes one `_`.
- Go's `strings.ToLower`/`ToUpper` map one rune at a time: `İ` → `i`, `ΟΔΟΣ` → `οδοσ`, `ß` stays. The Go runner uses `x/text/cases`, and the lowercase/uppercase step descriptions in `$meta.normalize_steps` now say so.
- Python's `str.strip()` and JS's `trim()` use different whitespace sets from the trim step, so every runner writes the set out.

- [x] Test (all four, via `cases.json`): `phone` rejects `"+14155552671\n"` and `"+1٣٣٣"`; `char` accepts an emoji (one code point) and rejects `"ab"`; the trim/case/lookup cases above. `dev/test/langs.test.mjs` runs the JS reference on the same cases.
- [x] Negative check: a `dist` copy with the 0.2.0 `phone`/`hostname` patterns fails in Python (Unicode digit), Go and Rust (lookahead won't compile). TS passes, which is why a JS-only test suite never caught it.
- [x] `npm run check:langs` (all four ok), `npm test` 156/156. Commit `test: prove dist/scalars.json in go, python, rust and ts`.
