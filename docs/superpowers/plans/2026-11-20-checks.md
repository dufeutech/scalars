# Checks (check digits and 64-bit ranges) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `validate` rejects identifiers with a wrong check digit (`gtin`, new `gln`, `iban`, `lei`, `isbn`, `orcid`) and string-encoded integers outside the 64-bit range (`int64`, `uint64`) in all four generated languages and the dev reference; CI runs every check on push.

**Architecture:** A type names its algorithm with a new core key `check`; the seven names and their meanings live in `schema/scalar.schema.json` `$defs.check` and are copied to `dist/scalars.json` `$meta.checks`, exactly like `normalize_steps`. Each engine implements the seven algorithms once and runs the type's one after the pattern matches. A new example list `check_invalid` holds values that pass the pattern but fail the check.

**Tech Stack:** Node 22+ build/tests (node:test, ajv, PGlite), generated Python / TypeScript / Go / Rust.

**Spec:** `docs/superpowers/specs/2026-11-20-checks-design.md`

## Global Constraints

- Never rename or move an existing field of `dist/scalars.json` (0.3.0 stable shape). Only add.
- `validate` stays O(n) worst case. The check runs only after the pattern matched. Mod 97 and the range compare work digit by digit, never with big integers.
- Never edit `dist/` by hand: change `src/`, `schema/` or `dev/codegen/`, then `cd dev && npm run build`.
- Write anything containing regex backslashes with the Edit/Write tools, never Bash heredocs (the Bash tool collapses `\\`).
- Check names, exactly: `gs1_mod10`, `iso7064_mod97_10`, `iban`, `isbn`, `iso7064_mod11_2`, `int64_range`, `uint64_range`.
- Assignments: `gtin`, `gln` → `gs1_mod10`; `lei` → `iso7064_mod97_10`; `iban` → `iban`; `isbn` → `isbn`; `orcid` → `iso7064_mod11_2`; `int64` → `int64_range`; `uint64` → `uint64_range`. Children inherit (`uint64`'s base is checked when resolving; a child that is not the same range sets `"check": null`).
- One error text per type. Reword the five check-digit ones so they also cover a wrong check digit; reword `int64`/`uint64` errors to mention the range if they do not.
- Done means: `npm test` and `npm run check:langs` both pass, and `dist/` is rebuilt and committed.

## Algorithms (the meaning every implementation follows; also the `$defs.check` descriptions)

- `gs1_mod10`: digits only. From the right, the check digit has weight 1, then weights alternate 3, 1, 3, …; the weighted sum is a multiple of 10.
- `iso7064_mod97_10`: read left to right; a digit d does `r = (r*10 + d) % 97`, a letter A-Z (value 10-35) does `r = (r*100 + v) % 97`; valid when `r == 1`.
- `iban`: the first four characters moved to the end, then `iso7064_mod97_10`.
- `isbn`: 13 characters use `gs1_mod10`. 10 characters: value of position i (0-based) times (10 − i), with `X` or `x` = 10; the sum is a multiple of 11.
- `iso7064_mod11_2`: skip hyphens. For each character but the last, `t = (t + digit) * 2`; the check value is `(12 - t % 11) % 11`, written `X` when 10; valid when the last character equals it.
- `int64_range`: an optional `-` then digits; leading zeros ignored; the value is between -9223372036854775808 and 9223372036854775807.
- `uint64_range`: digits; leading zeros ignored; the value is at most 18446744073709551615.

Reference body (JS, `dev/lib/reference.mjs`); the engines port it:

```js
const gs1 = (s) => { let t = 0; for (let i = 0; i < s.length; i++) t += (s.charCodeAt(s.length - 1 - i) - 48) * (i % 2 ? 3 : 1); return t % 10 === 0; };
const mod97 = (s) => { let r = 0; for (const c of s) { const v = parseInt(c, 36); r = (v > 9 ? r * 100 + v : r * 10 + v) % 97; } return r === 1; };
const isbn10 = (s) => { let t = 0; for (let i = 0; i < 10; i++) t += (/[Xx]/.test(s[i]) ? 10 : s.charCodeAt(i) - 48) * (10 - i); return t % 11 === 0; };
const mod11_2 = (s) => { s = s.replaceAll("-", ""); let t = 0; for (let i = 0; i < s.length - 1; i++) t = (t + s.charCodeAt(i) - 48) * 2; const r = (12 - t % 11) % 11; return s.at(-1) === (r === 10 ? "X" : String(r)); };
// Digits compared as text: drop leading zeros, then shorter wins, equal length compares lexicographically. O(n).
const atMost = (digits, max) => { const d = digits.replace(/^0+(?=.)/, ""); return d.length < max.length || (d.length === max.length && d <= max); };
export const CHECKS = {
    gs1_mod10: gs1,
    iso7064_mod97_10: mod97,
    iban: (s) => mod97(s.slice(4) + s.slice(0, 4)),
    isbn: (s) => (s.length === 13 ? gs1(s) : isbn10(s)),
    iso7064_mod11_2: mod11_2,
    int64_range: (s) => (s[0] === "-" ? atMost(s.slice(1), "9223372036854775808") : atMost(s, "9223372036854775807")),
    uint64_range: (s) => atMost(s, "18446744073709551615"),
};
```

## Review Focus

- **Spaced or hyphenated input** (`"0614 1410 0001 2"`, `"0-306-40615-2"`, `" de89 3704 0044 0532 0130 00 "`). The checksum must run on the normalized value, so these pass. Covered by `validate` cases in Task 1.
- **Lowercase `x` in an ISBN-10** (`"080442957x"`). The pattern allows it, so the checksum must count it as 10. Covered by a `validate` case in Task 1.
- **Inheritance:** a type built on a checksum type with `"check": null` must lose the checksum. Covered by a resolve test in Task 1.
- **Unknown checksum name in source.** The build must fail at resolve time, not at runtime. Covered by a resolve test in Task 1.
- **Leading zeros on a 64-bit value** (`"000000000000000000000001"`). The value fits, so it must pass even though it's longer than 19 digits. Covered by a `validate` case in Task 1.
- **Very long hostile input** on a checksum type. The length gate and pattern reject it before the checksum runs. Covered by a `hostile` case in Task 1.
