# Post-0.6.0 follow-ups Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the two minors deferred from the 0.6.0 review. Go reports `malformed` (not `too_long`) for an encoded lone surrogate on a short type, as JS and Python do. The README stops saying models are unreleased. Ships as 0.6.1.

**Architecture:** In Go, a lone surrogate arrives as the 3 bytes `ED A0..BF 80..BF` (WTF-8), and `utf8.RuneCountInString` counts it as 3. JS and Python count a lone surrogate as 1. Go's length count for the gates should count that 3-byte form as one code point, and each other invalid byte as one (as now). Valid UTF-8 counts the same as before, so only the reason for malformed text changes.

**Tech Stack:** Go ≥1.21 (generated `dist/go/scalars.go` from `dev/codegen/engine.go`), Node test runner.

**Spec:** the 0.6.0 design in git history (`docs/superpowers/specs/2026-11-21-lists-and-reasons-design.md`, removed in `685d5e8`). Reasons section: "`malformed`: text that isn't well-formed Unicode", order "early length gate → malformed". Lengths count code points, and a lone surrogate counts as one, as `docs/HANDOFF.md` records.

## Global Constraints

- `validate` stays O(n) worst case. `IsValid` allocates nothing. No new dependencies, and no package-level init code in Go.
- Never edit `dist/` by hand: change `dev/codegen/engine.go` and run `npm run build` from `dev/`.
- The Bash tool collapses `\\` to `\`. Any edit holding a backslash (Go byte escapes like `"\xed\xa0\x80"`) goes through the file editor.
- Each task ends green: `npm run build && npm test && npm run check:ts && npm run check:langs` from `dev/`.

## Review Focus

1. **Truncated surrogate encodings.** `"\xed\xa0"` (2 bytes, cut short) is not the 3-byte form, so it counts as 2 invalid bytes. On `char` that's `too_long`. Task 1 pins it.
2. **A surrogate pair encoded as two 3-byte forms** (`"\xed\xa0\xbd\xed\xb8\x80"`, CESU-8 for 😀) counts as 2. JS would see one valid pair, but Go has no way to tell, and `utf8.ValidString` rejects it anyway. On `char` that's `too_long`. Task 1 pins it.
3. **Valid text unchanged.** Every existing shared case and hostile case passes with the same reason, and the hostile timings stay under 2 s.
